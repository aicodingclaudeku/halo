# RC-S133.6.2 — Sidik Import (v81), Label SHU Posisi Keuangan, Koreksi Transaksi dari History

Basis: KOPKU RC-S133.6.1 / Desktop 1.0.16. Hasil: source **RC-S133.6.2** dan **KOPKU Desktop 1.0.17**. Skema database **v80 → v81** (aditif). Tidak ada jurnal penutup tahun.

## §A. Keputusan pengguna yang diterapkan
1. **Import ganda — WAJIB DIPERBAIKI.** Sidik isi data disimpan permanen (bukan nama berkas/NIK); migrasi v81 setelah backup, pemeriksaan migrasi, dan uji upgrade; berkas identik ditolak walau namanya berubah; import yang gagal sebagian dapat dilanjutkan tanpa menggandakan baris yang sudah masuk.
2. **Label SHU Posisi Keuangan — PERBAIKI LABEL SAJA.** Angka & rumus tetap; label "SHU Tahun Sebelumnya yang Belum Dibagikan dan SHU Tahun Berjalan" bila memang dua komponen itu yang digabung; baris SHU dapat diketuk untuk melihat SHU berjalan & SHU tahun sebelumnya. Tanpa jurnal penutup.
3. **Koreksi transaksi dari History — DENGAN AUDIT TRAIL.** Setoran simpanan, pencairan pinjaman, angsuran: pembalikan + pencatatan ulang, alasan, otorisasi, ID transaksi asal, jurnal tertelusur; validasi khusus untuk transaksi lanjutan & periode tertutup.

## §B. Import ganda — sidik isi baris (temuan T-05)
### §B.1 Cara kerja
- Setiap baris sheet 1–5 (Anggota, Simpanan, Berjangka, Pinjaman, Aset) diberi **sidik SHA-256 dari isi baku** (`src/import/SidikImport.ts`, implementasi murni, vektor uji FIPS lulus):
  - anggota dikenali dari **nama (huruf kecil, spasi dirapikan) + NIK (bila ada) + tanggal bergabung**, bukan Kode Anggota berkas; baris simpanan/pinjaman/berjangka merujuk identitas anggota yang sama;
  - kolom keadaan **tidak** ikut sidik: Angsuran Sudah Dibayar, sisa pokok, tunggakan, Sumber Dana, Rekening Bank — pinjaman/setoran yang sama tetap dikenali walau angka keadaannya diperbarui;
  - isi identik yang muncul berulang dalam satu berkas dibedakan urutan kemunculannya (#0, #1, …).
- Sidik baris yang **sudah tertulis ke buku** disimpan di tabel baru `import_data_awal_sidik` (UNIQUE `sidik`), langsung sesudah baris itu berhasil (bukan di akhir import) — import yang terhenti di tengah tetap meninggalkan catatan.
- Pinjaman yang **sudah cair tetapi angsurannya gagal** dicatat berstatus `SEBAGIAN` → import ulang melewatinya (tidak dicairkan dua kali).
- Sidik dibaca **sebelum** baris pertama ditulis; bila tabel sidik tidak terbaca, import berhenti (gagal tertutup).
- Sheet 6 (Jasa Dibayar) & 7 (Saldo Awal Akun) tidak bersidik: keduanya sudah idempoten (jasa per anggota ditimpa; saldo awal akun ditolak bila sudah ada).
- Aset tetap: baris tetap melewati penjaga lama (`jalankanMigrasiAset` melewati nomor aset yang sudah ada — ekspektasi tes lama dipertahankan); sidik hanya mencegah totalnya dijumlahkan dua kali ke saldo awal otomatis.

### §B.2 Pratinjau (tombol Import)
| Keadaan | Tingkat | Hasil |
|---|---|---|
| Seluruh baris bersidik sudah pernah diimpor (berkas identik, nama boleh beda) | **BLOKIR** "Berkas ini sudah pernah diimpor" (tanggal & nama berkas pertama) | Tombol Import terkunci |
| Sebagian sudah diimpor | **PERINGATAN** "N baris sudah pernah diimpor — akan DILEWATI" (rincian sheet/baris) | Import jalan; baris lama dilewati |
| Anggota tanpa NIK, nama + tanggal bergabung sama dengan anggota yang ada, tanpa sidik (data sebelum v81 / input menu) | **PERINGATAN** "Anggota tanpa NIK kemungkinan sudah ada" | Import jalan bila pengguna yakin |
| NIK milik anggota yang sudah ada | BLOKIR (RC-S133.6.1) — **kecuali** baris anggota yang sidiknya tercatat (lanjutan import) | — |

Hasil import & Riwayat Import menampilkan **"dilewati"** per sheet beserta rinciannya (disimpan di ringkasan riwayat; kolom log v74 tidak diubah).

### §B.3 Keterbatasan yang disengaja
1. Dua transaksi berbeda yang **isinya identik** (anggota, tanggal, nominal sama) di **dua berkas berbeda** dianggap sama; yang kedua dilewati dan dilaporkan. Catat lewat menu transaksi biasa.
2. Data yang diimpor **sebelum v81** tidak punya sidik dan **tidak direkonstruksi** (mengarang sidik tidak dilakukan). Perlindungannya: BLOKIR NIK terdaftar + PERINGATAN anggota-mirip.
3. Jendela sempit: bila aplikasi mati tepat di antara komit baris dan penulisan sidiknya, baris itu dapat diproses lagi pada import ulang (service domain membuka transaksinya sendiri).

## §C. Migrasi v81
- **Salinan pengaman sebelum migrasi** (`cadangkanSebelumMigrasi` di `db.ts`, untuk setiap upgrade versi): `VACUUM INTO` ke folder database bernama `pra-migrasi-v<lama>-ke-v<baru>-<UTC>.db`. **Bila salinan gagal → migrasi dihentikan**: versi tetap, tidak ada DDL, pesan jelas, percobaan berikutnya mengulang. Database in-memory dilewati.
- `migrasiV81` (aditif, idempoten): tabel `import_data_awal_sidik`, `koreksi_transaksi` (DDL dari `CREATE_TABLES_SQL`, termasuk indeks UNIQUE), kolom riwayat `sidik_berkas` (NULL) & `total_dilewati` (DEFAULT 0). Tidak ada baris lama yang diubah.
- `ResetDataPlan`: kedua tabel baru masuk daftar hapus mode TRANSAKSI (`koreksi_transaksi` sebelum `journal`).
- **HP & desktop harus versi skema sama** (sinkron menolak beda versi): APK baru dari source ini diperlukan.

## §D. Label SHU Posisi Keuangan (temuan T-07)
- `getPosisiKeuangan` menambah `rincianLabaBerjalan` = { `shuTahunBerjalan` = `getLabaRugi(awal tahun buku, tanggal laporan)` (= LHU), `shuTahunSebelumnya` = `labaBerjalan − shuTahunBerjalan` }. **`labaBerjalan`, total, rumus tidak berubah.**
- Label hanya berubah pada keadaan "belum dihitung" tahun berjalan (label yang dikeluhkan):
  - tahun sebelumnya ≠ 0 dan tahun berjalan ≠ 0 → **"SHU Tahun Sebelumnya yang Belum Dibagikan dan SHU Tahun Berjalan"**;
  - tahun sebelumnya ≠ 0, tahun berjalan = 0 → "SHU Tahun Sebelumnya yang Belum Dibagikan";
  - tahun sebelumnya = 0 → label lama. Label status DIHITUNG/DIBAGIKAN tidak diubah.
- Layar: baris SHU **dapat diketuk** (ikon panah) → dua baris rincian (mode tunggal & komparatif). Label ikut ke ekspor Excel/PDF dan Perubahan Ekuitas (label padanan). Rincian ketuk hanya di layar.

## §E. Koreksi transaksi dari History (temuan T-08)
### §E.1 Alur
History Transaksi → detail → **Koreksi Transaksi** → form: data asal, catatan, **alasan wajib (≥5 karakter)**, pilihan **catat ulang dengan data yang benar** (default aktif). Satu transaksi database:
1. `reverseJournal` — jurnal asal **REVERSED** (tidak diedit/dihapus), pembalik bertanggal hari ini;
2. pemulihan buku pembantu (lihat tabel);
3. (opsional) pencatatan ulang lewat fungsi service yang sama dengan input biasa (`catatDataAwalSimpananDb`, `cairkanPinjamanDb`, `bayarAngsuranDb` — **ekstraksi murni** dari fungsi lama tanpa transaksi sendiri; logika tidak diubah, pembungkus lama tetap);
4. jejak `koreksi_transaksi` (jenis, jurnal asal/pembalik/pengganti, entitas, alasan, `diotorisasi_oleh`, data sebelum/sesudah JSON) + `audit_log` action `KOREKSI`.
Gagal di langkah mana pun → seluruhnya batal.

| Jenis | Pemulihan buku pembantu | Pencatatan ulang |
|---|---|---|
| Setoran simpanan (`SIMPANAN_DATA_AWAL` — Setor Simpanan & import) | baris `KOREKSI` per baris asal (pola `koreksiSimpanan`) | tanggal, pokok, wajib, sukarela, Kas/Bank |
| Pencairan pinjaman | pinjaman → DISETUJUI, `pencairan_journal_id` kosong (pola `hapusPencairanPinjaman`) | cair ulang: tanggal, Kas/Bank (jumlah & jadwal tetap) |
| Angsuran (`ANGSURAN_POKOK`) | jadwal: porsi pokok/jasa/denda & `jasa_dimuka` dikembalikan, status dihitung ulang; Piutang Jasa (`kas_diterima`) dipulihkan sebesar kredit di jurnal asal; baris pembalik **negatif** di `angsuran_pembayaran` (`reversal_of_id`) bertanggal pembayaran asal; LUNAS → AKTIF | bayar ulang jadwal yang sama: tanggal, nominal, Kas/Bank |

### §E.2 Validasi khusus (gagal tertutup — tombol tidak muncul, alasan ditampilkan)
- Umum: hanya POSTED; bukan jurnal pembalik; belum pernah dikoreksi; periode transaksi asal **CLOSED** → tolak; periode hari ini CLOSED → tolak.
- Setoran: anggota tidak AKTIF → tolak; saldo jenis simpanan tidak boleh **negatif di titik mana pun** setelah pembalikan (penarikan sesudahnya) — boleh bila pencatatan ulang menutupnya; Simpanan Pokok yang dibalik wajib dicatat ulang bila anggota punya pinjaman berjalan; SHU tahun bukunya **DIAJUKAN_RAT/DISAHKAN_RAT/DIBAGIKAN** → tolak (DIHITUNG → catatan hitung ulang); bunga sukarela yang sudah diproses → catatan (selisih dibukukan otomatis sebagai KOREKSI oleh proses bunga berikutnya).
- Pencairan: sudah ada angsuran → tolak (koreksi angsuran dulu); sudah ada **akrual jasa** → tolak; akad ulang; fee integral EIR → tolak.
- Angsuran: hanya **pembayaran terakhir** pinjaman; pelunasan dipercepat → tolak; akrual jasa periode itu dibuat **sesudah** pembayaran → tolak; jasa dimuka sudah diakui → tolak; hapus buku/akad ulang → tolak; SHU final → tolak.
- Izin: `history_transaksi` edit + izin domain (`simpanan` edit / `pinjaman` approve / `pinjaman` edit; pencatatan ulang juga melewati izin service aslinya).
- Setoran `SIMPANAN_POKOK/WAJIB/SUKARELA` (jalur lama `koreksiSimpanan`): tombol Batalkan disembunyikan bila pembatalan membuat saldo negatif. Fungsi `koreksiSimpanan` sendiri tidak diubah.
